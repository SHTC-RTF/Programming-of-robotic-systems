# Лабораторная работа №9: Реализация надежного бинарного протокола типа «Запрос–Ответ» и потоковой телеметрии по UART с вычислением контрольной суммы CRC

**Продолжительность:** 4 академических часа

**Целевая аудитория:** Студенты 3–4 курсов 

**Аппаратная база:** Микроконтроллер К1921ВГ01Т (RISC-V) / ПК со средой телеметрии (Python / Serial Studio)

## 1\. Цель работы

- Изучить принципы проектирования отказоустойчивых бинарных коммуникационных протоколов для робототехнических систем.
- Реализовать прием пакетов переменной длины по интерфейсу UART с использованием циклического буфера ОЗУ, контроллера DMA и прерывания по таймауту/простою шины (**Receiver Timeout / Idle Line**).
- Освоить алгоритмы кадрирования бинарных потоков (байт-стаффинг **COBS** — Consistent Overhead Byte Stuffing) и аппаратное/программное вычисление контрольных сумм (**CRC16-CCITT / CRC32**).
- Спроектировать конечный автомат разбора пакетов (FSM Parser) и совместить два режима обмена: асинхронную периодическую передачу телеметрии привода (потоковый режим) и детерминированную обработку команд типа «Запрос–Ответ» (RPC-режим).

## 2\. Теоретические сведения

### 2.1. Недостатки текстовых протоколов (ASCII) в робототехнике

Передача команд и телеметрии в текстовом виде (например, `"SET_SPEED 1200\n"`) неэффективна для контуров реального времени:

- **Низкая плотность информации:** 32-битное число с плавающей точкой `float` в бинарном виде занимает 4 байта, а в строковом — до 10–12 байт.
- **Высокие накладные расходы процессора:** функции форматирования и парсинга (`sprintf`, `sscanf`, `atof`) требуют динамического разбора строк, расходуют стек и работают неделитерминированно долго.
- **Слабая помехозащищенность:** текстовые терминаторы строк (`\r\n`) легко имитируются шумами линии, что приводит к ложным срабатываниям без валидации контрольной суммой.

### 2.2. Архитектура бинарного кадра и кадрирование COBS

Бинарный фрейм может содержать любые байты полезной нагрузки в диапазоне `0x00..0xFF`. Если использовать фиксированный маркер начала/конца пакета (например, байт `0x00`), он может случайно встретиться внутри передаваемого числа `float`.

**Алгоритм COBS (Consistent Overhead Byte Stuffing):** COBS кодирует произвольный массив байт так, что результирующий пакет **гарантированно не содержит байта `0x00`**. Это позволяет использовать единственный байт `0x00` в качестве абсолютного разделителя кадров (Delimiter):

- Накладные расходы: ровно 1 дополнительный байт на каждые 254 байта данных.
- При потере синхронизации приемник мгновенно восстанавливает начало следующего кадра по первому встретившемуся `0x00`.

```
Структура полезной нагрузки пакета (Payload)
┌──────────┬──────────┬──────────┬─────────────────────────────┬──────────────┐
│  SOF     │ Type/Cmd │ Seq Num  │       Данные (Data)         │   CRC-16     │
│  (0xAA)  │ (1 байт) │ (1 байт) │        (N байт)             │  (2 байта)   │
└──────────┴──────────┴──────────┴─────────────────────────────┴──────────────┘
                                  │
                                  ▼ Кодирование COBS
┌──────────────────────────────────────────────────────────────┬──────────────┐
│                 COBS-кодированный массив                     │  Фрейм-стоп  │
│                   (не содержит 0x00)                         │    (0x00)    │
└──────────────────────────────────────────────────────────────┴──────────────┘
```


### 2.3. Контроль целостности: алгоритм CRC16-CCITT

Для обнаружения одиночных, двойных и пачечных битовых ошибок в канале связи применяется циклический избыточный код **CRC-16** (полином $X^{16} + X^{12} + X^5 + 1$, порождающее число `0x1021`, инициализация `0xFFFF`).

Если рассчитанная на стороне МК контрольная сумма не совпадает со значением в хвосте принятого пакета, кадр отбрасывается без выполнения команды, а отправителю отсылается отрицательное подтверждение (`NACK`).

### 2.4. Прием пакетов через DMA и таймаут шины UART

Для исключения прерываний на каждый принятый байт прием организуется через канал DMA:

1. Контроллер DMA складывает входящие байты в циклический буфер.
2. Когда передача со стороны ПК завершается, линия UART переходит в состояние логической «1» (пассивное состояние).
3. Аппаратный блок UART фиксирует простой линии длительностью более одного байтового фрейма (**Receiver Timeout Interrupt**) и генерирует прерывание.
4. Процессор считывает текущий указатель DMA, определяет число фактически принятых байт и передает блок на раскодирование COBS и парсинг.

## 6\. Программная реализация

### 6.1. Модуль расчета CRC16 и кадрирования COBS (`protocol_utils.c`)

```c
#include <stdint.h>
#include <stddef.h>

// Расчет CRC16-CCITT (Полином 0x1021, Init 0xFFFF)
uint16_t CRC16_CCITT(const uint8_t *data, size_t length)
{
    uint16_t crc = 0xFFFF;
    for (size_t i = 0; i < length; i++) {
        crc ^= (uint16_t)data[i] << 8;
        for (uint8_t bit = 0; bit < 8; bit++) {
            if (crc & 0x8000) {
                crc = (crc << 1) ^ 0x1021;
            } else {
                crc = crc << 1;
            }
        }
    }
    return crc;
}

// Кодирование COBS: src не должен содержать маркер 0x00 после кодирования
size_t COBS_Encode(const uint8_t *src, size_t src_len, uint8_t *dst)
{
    size_t read_idx = 0;
    size_t write_idx = 1;
    size_t code_idx = 0;
    uint8_t code = 1;

    while (read_idx < src_len) {
        if (src[read_idx] == 0) {
            dst[code_idx] = code;
            code_idx = write_idx++;
            code = 1;
        } else {
            dst[write_idx++] = src[read_idx];
            code++;
            if (code == 0xFF) {
                dst[code_idx] = code;
                code_idx = write_idx++;
                code = 1;
            }
        }
        read_idx++;
    }
    dst[code_idx] = code;
    return write_idx; // Возвращает длину закодированных данных
}

// Декодирование COBS: восстанавливает исходный массив с нулями
size_t COBS_Decode(const uint8_t *src, size_t src_len, uint8_t *dst)
{
    size_t read_idx = 0;
    size_t write_idx = 0;

    while (read_idx < src_len) {
        uint8_t code = src[read_idx++];
        if (code == 0) return 0; // Ошибка: нулевой байт внутри пакета не допускается

        for (uint8_t i = 1; i < code; i++) {
            if (read_idx >= src_len) return 0;
            dst[write_idx++] = src[read_idx++];
        }
        if (code < 0xFF && read_idx < src_len) {
            dst[write_idx++] = 0;
        }
    }
    return write_idx; // Длина раскодированных полезных данных
}
```

### 6.2. Драйвер протокола обмена (`protocol_handler.c`)


```c
#include "k1921vg01t.h"
#include <stdint.h>
#include <stdbool.h>
#include <string.h>

#define RX_BUFFER_SIZE  256
#define TX_BUFFER_SIZE  256

static uint8_t raw_rx_buf[RX_BUFFER_SIZE];
static uint8_t decoded_payload[RX_BUFFER_SIZE];
static uint8_t tx_frame_buf[TX_BUFFER_SIZE];

extern uint16_t CRC16_CCITT(const uint8_t *data, size_t length);
extern size_t COBS_Encode(const uint8_t *src, size_t src_len, uint8_t *dst);
extern size_t COBS_Decode(const uint8_t *src, size_t src_len, uint8_t *dst);

// Целевые переменные контура управления
volatile float setpoint_rpm = 0.0f;
volatile float actual_rpm = 0.0f;
volatile float motor_current_amps = 0.0f;
volatile uint32_t motor_encoder_ticks = 0;

/**
 * @brief Отправка потокового кадра телеметрии (Пакет 0x82)
 */
void Protocol_Send_Telemetry(void)
{
    uint8_t payload[32];
    payload[0] = 0xAA; // Маркер начала (SOF)
    payload[1] = 0x82; // Тип кадра: телеметрия
    payload[2] = 0x00; // Sequence number

    // Копирование полей (Little-Endian)
    memcpy(&payload[3], (void*)&actual_rpm, 4);
    memcpy(&payload[7], (void*)&motor_current_amps, 4);
    memcpy(&payload[11], (void*)&motor_encoder_ticks, 4);
    payload[15] = 0x01; // Байт статуса (привод активен)

    // Расчет контрольной суммы по полям 0..15
    uint16_t crc = CRC16_CCITT(payload, 16);
    payload[16] = (uint8_t)(crc & 0xFF);
    payload[17] = (uint8_t)((crc >> 8) & 0xFF);

    // Кодирование COBS
    size_t enc_len = COBS_Encode(payload, 18, tx_frame_buf);
    tx_frame_buf[enc_len] = 0x00; // Терминатор кадра (разделитель)

    // Отправка в UART через DMA или кольцевой буфер
    for (size_t i = 0; i <= enc_len; i++) {
        while (UART0->FR_bit.TXFF); // Ожидание места в TX FIFO
        UART0->DR = tx_frame_buf[i];
    }
}

/**
 * @brief Разбор принятого раскодированного пакета
 */
void Protocol_Process_Packet(const uint8_t *buf, size_t len)
{
    // Минимальный пакет: SOF(1) + CMD(1) + SEQ(1) + CRC(2) = 5 байт
    if (len < 5) return;
    if (buf[0] != 0xAA) return; // Неверный заголовок

    // Проверка контрольной суммы
    uint16_t received_crc = (uint16_t)buf[len - 2] | ((uint16_t)buf[len - 1] << 8);
    uint16_t calculated_crc = CRC16_CCITT(buf, len - 2);

    if (received_crc != calculated_crc) {
        // Ошибка CRC: отправка NACK (0x81, код ошибки 1)
        return;
    }

    uint8_t cmd = buf[1];
    switch (cmd) {
        case 0x01: // PING -> ответ ACK (0x81, код 0)
            break;

        case 0x02: // SET_TARGET_SPEED (4 байта float)
            if (len == (5 + 4)) {
                memcpy((void*)&setpoint_rpm, &buf[3], 4);
            }
            break;

        case 0x04: // EMERGENCY_STOP
            setpoint_rpm = 0.0f;
            // Аппаратный останов через ePWM Trip-Zone
            EPWM0->TZFRC_bit.OST = 1;
            break;

        default:
            break;
    }
}

/**
 * @brief Прерывание UART0 по таймауту приемника (окончание пачки байт)
 */
void UART0_IRQHandler(void)
{
    if (UART0->RIS_bit.RTRIS) // Receive Timeout
    {
        uint16_t bytes_read = 0;
        while (!UART0->FR_bit.RXFE) {
            if (bytes_read < RX_BUFFER_SIZE) {
                raw_rx_buf[bytes_read++] = (uint8_t)(UART0->DR & 0xFF);
            } else {
                volatile uint32_t dummy = UART0->DR; // Сброс при переполнении
            }
        }

        // Если в конце принят терминатор 0x00, декодируем пакет
        if (bytes_read > 1 && raw_rx_buf[bytes_read - 1] == 0x00) {
            size_t dec_len = COBS_Decode(raw_rx_buf, bytes_read - 1, decoded_payload);
            if (dec_len > 0) {
                Protocol_Process_Packet(decoded_payload, dec_len);
            }
        }

        UART0->ICR = (1 << 6); // Сброс флага Receive Timeout Interrupt (RTIC)
    }
}
```

### 6.3. Тестовый скрипт верхнего уровня на Python (`host_test.py`)

```python
import serial
import struct
import time
from cobs import cobs

def crc16_ccitt(data: bytes) -> int:
    crc = 0xFFFF
    for byte in data:
        crc ^= (byte << 8)
        for _ in range(8):
            if crc & 0x8000:
                crc = ((crc << 1) ^ 0x1021) & 0xFFFF
            else:
                crc = (crc << 1) & 0xFFFF
    return crc

def send_target_speed(ser: serial.Serial, rpm: float):
    # Кадр: SOF (0xAA) + CMD (0x02) + SEQ (0x01) + float data (4 байта)
    payload = struct.pack("<BBBf", 0xAA, 0x02, 0x01, rpm)
    crc = crc16_ccitt(payload)
    packet_to_encode = payload + struct.pack("<H", crc)
    
    # Кадрирование COBS и добавление стоп-байта
    encoded = cobs.encode(packet_to_encode) + b'\x00'
    ser.write(encoded)

if __name__ == "__main__":
    ser = serial.Serial('COM5', 115200, timeout=0.1)
    time.sleep(1.0)
    print("Отправка уставки скорости 450.0 RPM...")
    send_target_speed(ser, 450.0)

    # Прием телеметрии
    rx_buffer = bytearray()
    while True:
        byte = ser.read(1)
        if byte:
            if byte == b'\x00':
                if len(rx_buffer) > 0:
                    try:
                        decoded = cobs.decode(bytes(rx_buffer))
                        if len(decoded) == 18 and decoded[0] == 0xAA and decoded[1] == 0x82:
                            # Проверка CRC
                            calc_crc = crc16_ccitt(decoded[:16])
                            recv_crc = struct.unpack("<H", decoded[16:18])[0]
                            if calc_crc == recv_crc:
                                speed, curr, enc, status = struct.unpack("<fffB", decoded[3:16])
                                print(f"Телеметрия: Скорость={speed:.1f} RPM, Ток={curr:.2f} А, Энкодер={enc}")
                    except Exception as e:
                        pass
                    rx_buffer.clear()
            else:
                rx_buffer.append(byte[0])
```

2. В чем заключается алгоритм кодирования COBS (Consistent Overhead Byte Stuffing)? Какую проблему он решает при кадрировании бинарных потоков?
3. Почему контрольная сумма CRC обладает значительно более высокой обнаруживающей способностью для пачек ошибок (Burst Errors) по сравнению с простой суммой байт (CheckSum)?
4. Каким образом прерывание по таймауту приемника (Receive Timeout) позволяет МК определять границы пакетов переменной длины без ручного подсчета байт в прерываниях?
5. Что произойдет в системе, если передача потоковой телеметрии с частотой 100 Гц будет выполняться через блокирующую отправку UART в теле высокоприоритетного прерывания контура привода?
